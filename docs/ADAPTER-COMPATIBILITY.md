# v0.6.15 AstrBot 接口修复

v0.6.18 补齐标准 `Record` 组件的原生发送映射，修复 v0.6.17 只支持文件回退、语音仍被组件白名单拒绝的问题。复用 v0.6.17 的流式上传，kind=voice；接受、查询、结果未知和释放规则与文件一致。使用 [AstrBot v4.29.4 MediaResolver](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/core/utils/media_utils.py) 的 audio/as_path 取得 WAV，解析器资源保持到上传结束；不截断、分段或设置时长上限。需 Hook 12 或后续兼容版，且 type_available.voice=true。入口在上传前明确记录缺失能力，提交和任务结束日志保留具体错误；不修改音乐插件，不在原生结果未知时自动补发文件。没有编写或运行测试、部署或主动发送；原生语音实际收件与播放仍待验收。

v0.6.17 增加标准 `File` 出站组件：普通回复和 `context.send_message` 共用原发送入口，解析附件后通过 Hook 的 `/wxcx/outbound/upload` 流式上传，不把 AstrBot 容器路径传给 Windows。需要配套 `MULTI-VERSION-20261113-12-CANDIDATE` 或提供该入口的后续 Hook；发送入口先核对一次 binary_upload 能力，旧 DLL 明确提示升级，不上传大文件。文件种类和语音时长不由适配器过滤，上传容量沿用 Hook 的 200 MiB 文件边界。文件任务沿用持久化意图、查询、未知结果和释放规则；HTTP 202 不代表收件。本轮仅本地实现、编译与打包，尚未实际发送验收。

v0.6.16 修复 GitHub v0.6.15 上传转码造成的中文名称和提示乱码，保留上述接口修复。

要求 AstrBot >=4.29.4,<5。继续使用 PC 微信 Hook HTTP API；不切换到 openclaw-weixin。

从 v0.6.14 或更早版本升级，请完整重启一次 AstrBot，以清除旧版本没有登记撤销信息的 Provider 修改。之后可以按下述生命周期重载插件。

## 数据与实例

- 新机器人将 `inbox_db` 留空，按机器人 ID 与微信账号生成独立的数据目录。
- 旧默认数据库只有在账号一致、且未被其他机器人绑定时才继续使用，不移动文件，不修改会话 ID。
- 自定义数据库路径仍有效，但会绑定机器人 ID 与账号，拒绝复用其他实例的数据。
- 数据库旁的 `.lock` 文件用于系统级排他租约；正常停止释放租约，进程退出后系统也会释放。锁文件本身可以保留，无需删除。
- 旧数据库包含多个账号时，自动路径会使用新的独立数据库；不自动拆分或删除混合历史。手动指定混合数据库将明确报错。

## 接收与发送

- 不合法或超过 96 KB 的入站事件记入 `rejected_events`，包含有界预览与原因。有效序号随事务推进，后续消息继续处理；数据库写入失败仍回滚游标。
- 无有效序号的异常事件无法单独计算下一个游标；若同批含有效事件，则跟随它们推进。不会伪造消息序号。
- 事件构造失败进入 `event_error`，不再堵塞待处理队列。
- `send_enabled=false` 时，标准发送入口明确报错。需要显式草稿时可调用 `await event.save_draft(chain)`，它不会产生 AstrBot 的 `response_sent` 标记；旧草稿不会自动发送。
- 出站图片使用 AstrBot 的共享 `MediaResolver.as_path()` 解析 URL、file URI、Base64 或本地路径，再校验 PNG/JPEG 与 4 MiB 限制。Hook 上传字节，读完即可退出解析作用域，自动清理解析器创建的临时文件，保留调用者原有文件。视频输入通过组件的 `convert_to_file_path()` 获取路径。Hook 的提交回执依然不等同于微信送达回执。
- 入站图片、语音、视频与引用附件仍输出标准组件。Inbox 的哈希媒体文件是持久化附件，不登记为事件临时文件；AstrBot 核心预处理产生的转换文件由核心登记和清理。

## 生命周期与模型兼容

- 插件停用、更新或重载时，通过 AstrBot 平台管理器停止本插件的平台实例。
- 插件加载时，如果平台管理器已经运行，将恢复已配置且启用的 Hook 机器人；首次启动交给 AstrBot 统一初始化，避免重复启动。
- 轮询失败更新平台错误状态，下一次成功轮询清除连接错误。
- 当前 AstrBot Responses 转换器没有公开的原生文件扩展接口，因此保留隔离在 `responses_files.py` 中的兼容层。只安装到当前文件请求选中的 Provider，不再遍历所有 Provider；停用时恢复本插件拥有的方法与内容类型注册，不覆盖其他扩展后续的修改。
- 探针直接使用转换函数生成请求，不再安装 Provider 修改。模型降级到未经适配的 Provider 时，文件不保证可读，请以实际附件内容为准；不会宣称已经被 API 接收。

本次未新增或修改测试代码。语法、静态检查和现有检查结果见交付说明；真实微信及模型 API 的收发需在部署环境验证。
