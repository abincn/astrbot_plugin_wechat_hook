# AstrBot、WeChat Hook 与连接插件的接收能力对照

当前实现：连接插件 **v0.5.1**。对照本地 Hook 源码/API 清单和 AstrBot `v4.29.4` 消息组件。
这是代码实现状态，尚未实机验收。接收到组件不等于所有模型都会理解它；资源能否取得仍取决于实际 Hook 与微信状态。

## 入站消息

| 消息 | AstrBot 表达 | Hook 能提供 | 连接插件 v0.5.1 |
| --- | --- | --- | --- |
| 文字（1） | `Plain` | 正文、来源、时间、ID | 已接入 |
| @ | `At` / `AtAll` | 显式 mentions、is_at_me | 已映射普通目标及 `notify@all`；不从正文猜测 |
| 图片（3） | `Image` | 媒体任务与原文件 | 下载并校验大小/SHA-256/格式，最大 12 MiB |
| 视频（43） | `Video` | 媒体任务与原文件 | 原视频下载并校验，最大 60 MiB；不抽帧或修改模型请求 |
| 语音（34） | `Record` | `/DownloadVoice` 返回本地已下载的 SILK | 核对来源 ID、长度、头部和帧边界，最大 4 MiB/6000 帧；复用 AstrBot 解码，不重复写解码器或直接调用 ASR |
| 文件（49/6） | `File` | 文件卡片、file 媒体任务 | 下载并校验大小/SHA-256，最大 24 MiB（含空文件）；原名称仅显示，不执行文件 |
| 文件传输通知（49/74） | `Plain` + `Json` | 阶段、状态、替代消息 ID | 已传递通知；实际文件仍使用后续内容消息 |
| 引用文字（49/57） | `Reply` + `Plain` | 原消息 ID、发送者、时间、原文及回复正文 | 已接入；ID 保持字符串，缺少有效 ID 时明确文字回退 |
| 引用图片/视频（49/57） | `Reply.chain` 中的 `Image` / `Video` | 引用源 ID、发送者、媒体元数据 | 按引用源下载；不拿外层 ID 当媒体源，缺少原始资源不能伪造附件 |
| 链接（49/5） | `Share` + 文字 | 标题、描述、URL | 已接入卡片和可读摘要；不自动抓取网页正文 |
| 小程序（49/33、36） | `Json` + 文字 | 标题、描述、app_id、username、page_path、URL | 已接入内嵌信息，不运行小程序 |
| 表情（47） | 成功下载后 `Image`；失败时文字提示 | 原始 XML 中的 CDN 资源线索、MD5 | 对 `qpic.cn` 的 HTTPS 资源校验 MD5/大小/图片格式后接入；没有 URL/MD5、其他域名或加密资源仅保留提示与 raw_message |
| 合并转发（49/19） | `Nodes` / `Node` + 文字摘要 | 原始应用 XML 中可能带 `recorditem`；无已核实的远程节点展开接口 | 展开消息内嵌文字/链接及最多两层嵌套转发；最多 40 个原始节点、16000 字正文，另加截断提示；节点图片/视频/语音/文件标记未展开 |
| 名片（42） | `Json` + 文字 | username、昵称、别名等卡片字段 | 已接入；不将字符串微信 ID 塞入整数/TODO 的 `Contact.id`，不自动加好友 |
| 位置（48） | `Location` + 文字 | 原始位置 XML | 已接入有效经纬度、地点名、地址；检查有限数及范围，不访问地图 |
| 系统通知/撤回（10000/10002） | `Plain` + `Json` | 原始正文/系统 XML，来源身份可能不完整 | 对方向、会话可确认的事件传递文字/叶子元数据；不自动删除历史或执行系统操作 |
| 其他应用/特殊类型 | `Plain` + `Json` + `raw_message` | 原始消息与部分卡片字段 | 通用接入可取得的元数据；无专用组件或底层资源时明确标记，不伪造完整业务支持 |
| 私聊 | `FRIEND_MESSAGE` | 明确的入站方向、对方会话与来源 | 已接入；复用以上内容转换，与群聊会话隔离 |
| 群聊 | `GROUP_MESSAGE` | 群、发送者、会话、方向 | 已接入，不由连接器配置群名单 |

## 接收与后续理解

- 语音的本地数据必须已被微信下载。`Record` 使用 AstrBot 已有 SILK 解码；转写和语音理解需要 AstrBot 对应依赖、ASR 或音频模型。连接器不调用不可用的 `/Voice2Text`。
- 文件进入 `File` 后，是否提取正文取决于 AstrBot 文件处理配置，不承诺任意文档或二进制都能被模型理解。
- 图片需要视觉模型或图片描述配置；视频组件本身不代表模型看到了画面。
- v0.5.1 移除连接器的视频抽帧、开关和模型请求钩子。群聊、私聊及引用视频均交付原始 `Video` 组件。
  模型直传或抽帧应由模型适配/独立媒体处理负责；接收视频不需要 ffmpeg，不代表模型已收到原视频内容。
  Agent v0.3.2 也已移除群内抽帧逻辑，旧 Agent v0.3.1 用户应升级。
- 单独安装连接器即可接收组件。私聊不应用群 Agent 名单、工作区或群工具策略；回复和访问控制由 AstrBot 配置。

## 仍受底层能力限制的部分

- 合并转发只展开消息中已经携带的内容；没有远程原文或节点媒体下载能力时，不能还原完整附件或无限层转发链。
- 表情暂不接加密 CDN 解密或未知资源域名；只有元数据时不能假称已取得图片。
- 文件 `resource_missing` 仍需在 Hook 侧排查；原文件打开失败（包括路径、权限或占用）也会返回该码，本轮未修复或替换 DLL。
- 位置/名片和其他特殊消息只转换收到的数据，不执行导航、加好友、进群、支付、通话等操作。
- 部分系统事件缺少可信方向/账号/会话时仍不分发，不能凭文本虚构来源；原始事件保留程度取决于 Hook。
- 原生发送仍仅文本与普通群 @，私聊也可回复文本；`/SendQuoteMsg` 在当前 Hook 返回 `501 structured_send_unsupported`，媒体/卡片发送尚不可用。

## 持久化与边界

v0.4.1 修正媒体来源参数：Hook 的 source_talker 是会话（群 ID/私聊对方 ID），不是群成员 ID；
引用下载保持原消息 msgsvrid，并使用有效的原会话或当前会话。下载日志通过 AstrBot 插件 logger 输出；
新媒体失败/未知或缺少消息 ID 时也输出缺附件提示与原因，避免图片/视频一直不可见。

原群会话保持 `账号|群ID`；新私聊为 `账号|dm|对方ID`。发送仅绑定当前账号、当前会话、有效入站来源；默认关闭真实发送，不自动重投历史草稿。
原生下载任务结果不确定时不重新创建；旧 held/failed/unknown 记录不自动回放。新媒体下载失败/未知时传递明确缺附件的元数据；不会把未验证文件交给模型。
XML 每次最多 96 KB、1200 个元素、24 层，拒绝 DTD/实体声明。转发单节点正文最多 2000 字；通用特殊消息最多 24 个叶子字段、单字段 500 字。
表情使用独立无 Hook 令牌的客户端，不跟随重定向，资源只通过 HTTPS 下载。
