# AstrBot、WeChat Hook 与连接插件的接收能力对照

基于已读 Hook 源码、现有 API 清单、AstrBot commit `3bebdd3918b1617c58de5a09a8b0800f8a02c4f9`，
以及连接插件 v0.3.1 的代码对照。**这是实现状态，不是所有类型都已经实机验收。**
Hook 的“有接口/有解析”不等于当前环境一定下载成功；AstrBot 的“有消息组件”也不等于任意模型都能理解内容。
尚未核实的能力不按支持计。

## 入站消息

| 消息 | AstrBot 的表达/处理入口 | Hook 能提供什么 | 当前连接插件 v0.3.1 |
| --- | --- | --- | --- |
| 文字（1） | `Plain` | 入站正文、发送者、会话、时间、消息 ID | 已转换并交给 AstrBot |
| @ | `At` / `AtAll` | 显式 mentions 与 is_at_me 元数据 | 已映射 @机器人；其他目标及 @全体尚未完整映射，不从文本猜测 @ |
| 图片（3） | `Image`，可进入视觉模型输入 | 媒体任务下载，返回大小、SHA-256、文件内容 | 下载/校验后交给 AstrBot；最大 12 MiB，需要有效 msgsvrid |
| 视频（43） | `Video`；本版本原生流程主要保留本地附件路径 | 视频媒体任务与原文件 | 已补视频下载/校验和 `Video` 转换；最大 60 MiB，不在连接器里调用模型 |
| 引用文字（49/57） | `Reply` + 内嵌 `Plain` | 原消息 ID、发送者、时间、原文及本次回复正文 | 已补 `Reply` 转换，消息 ID 保持字符串；无有效 ID 时只保留明确标记的文本回退 |
| 引用图片/视频（49/57） | `Reply.chain` 内嵌 `Image` / `Video` | 引用源 ID、发送者、媒体类型与原文件下载 | 已按引用源下载并嵌入引用链，不把外层消息 ID 当作媒体源 |
| 语音（34） | `Record`；转写另需 ASR/合适格式 | 语音元数据；`DownloadVoice` 提供 SILK 原始数据，不能等同现成 MP3 或转写文本 | 只入库，未接 `Record`、SILK 解码或 ASR |
| 普通文件（49/6） | `File`；正文提取取决于其他功能 | 文件卡片信息与 file 媒体任务；实际可用性依赖原生资源下载 | 只保留入库信息，未下载/交给 `File` |
| 表情（47） | `Face` 或下载后转换成 `Image` | 消息正文/原始资源线索；未核实完整表情下载链 | 只入库，未转换表情组件或资源 |
| 链接、小程序（49） | 可表达为 `Share`、`Json` 或明确的文本摘要；不等于微信原生卡片 | 已解析标题、链接、描述及部分小程序元数据 | 元数据保留入库，尚未交给相应 AstrBot 组件 |
| 名片（42） | 有 `Contact` 类型但源码标 TODO，也可退化为文本/JSON | 已解析 username、昵称等名片字段 | 当前类型过滤，不接入 |
| 合并转发 | `Forward` / `Node` / `Nodes` | 未核实节点展开接口，不能把原始应用消息当作完整转发链 | 未接入 |
| 位置等特殊消息 | 存在部分组件（如 `Location`，源码标 TODO），需逐项适配 | 未核实结构化接收能力，保留原始正文不代表完整支持 | 未接入 |
| 私聊 | `FRIEND_MESSAGE` | 规范化代码支持非群会话及收发方向 | 目前仅接收入站群消息，私聊仍被过滤 |

文件传输通知、撤回/入群等系统事件需要分别核对 Hook 事件结构与 AstrBot 分发机制；目前不宣称已接入。

## “接收”与“理解”

- 图片文件进入 AstrBot 后，是否进入模型还取决于唤醒条件、视觉模型或图片描述配置。
- `Video` 组件本身不保证模型看到了视频画面。旧 Group Agents 的视频分析是在下载后通过 ffmpeg 抽帧。
- 群 Agent v0.3.1 在已启用的群内提供“视频抽帧分析”开关：沿用约 0、3、9 秒三帧、960 像素宽、
  每帧 1.5 MB/每次解码 12 秒上限，再通过 AstrBot 的图片输入交给模型。
  需要本机 ffmpeg 和视觉模型；不能据此判断音轨或未抽取到的画面。
- 连接器单独安装也会输出 `Image`、`Video`、`Reply`；不依赖 Agent，但不负责额外的模型视频分析。

## 旧 Group Agents 与当前插件

旧后台已有图片/视频/文件的下载、校验与模型材料转换流程。
v0.3.0 连接器只迁入图片，视频停留在 `held_media`，引用文字也未转换成 `Reply`，属于迁移缺口。
v0.3.1 补齐本表的图片/视频/引用接入，并把视频模型抽帧留在 Agent 层；没有迁移整套旧后台或重复调用模型。

旧的 held/unknown/failed 记录不会在升级时自动重投或回放；升级后用新消息观察日志和状态。
下载不确定时不重新创建媒体任务，防止重复原生操作。校验失败的文件不会交给 AstrBot。

## 接收引用与发送引用是两种能力

本次接入的是 **收到引用消息 → 转成 AstrBot `Reply`**。
发回微信的原生引用发送 `/SendQuoteMsg` 在当前 Hook 返回 `501 structured_send_unsupported`，连接器不伪造成功。
当前真实发送仍仅支持文本和普通群 @；不能把收到了图片/视频/引用理解为也能发送这些类型。
